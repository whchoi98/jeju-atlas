리소스·기술 범위와 검증 기준

이 문서는 workshop/IMPLEMENTATION_PLAN.md와 저장소의 인프라·배포기·앱·Agent·라우터 소스를 연결한다. 기준은 2026-09-11에 읽은 소스이며, 참가자 계정의 배포 완료 보고서가 아니다. 아래 검증은 해당 장에서 확보해야 할 증거다.

infra/*.yaml 10개의 Resources 절에는 조건부 선언을 포함해 논리 리소스 94개, 리소스 유형 41개가 있다. 예를 들어 Parameters.VpcId.Type: AWS::EC2::VPC::Id는 기존 VPC를 받는 입력 타입이다. 이를 VPC 생성 리소스로 세지 않는다. IAM 허용 ARN, 주석, 출력값, 과거 운영 보고서도 생성 선언과 구분한다.

파일 경로는 저장소 루트 기준이다. 표의 장 파일은 모두 workshop/chapters/ 아래에 둔다. 장 배치는 구현 계획이며 작성·실행 완료를 뜻하지 않는다. 기존 docs/의 .local/... 자료는 비공개 과거 증거이므로 링크나 필수 다운로드로 사용하지 않는다.

소유권 표기

  • 공유: 사전에 제공받는 계정 기반·네트워크·DNS·인증서·서비스 접근 권한. 참가자 정리 대상이 아니다.
  • 실습: 격리된 작업 사본에서 팀 이름으로 생성하고 해당 팀의 실제 ARN/ID를 기록할 자원.
  • 보존: DeletionPolicy: Retain과 UpdateReplacePolicy: Retain이 선언된 실습 자원. 스택 삭제와 별도 정리가 필요하다.
  • 외부/로컬: 외부 데이터·서비스 또는 개발 환경·브라우저 자원. AWS 실습 스택의 소유 자원으로 세지 않는다.

static.yaml의 “shared assets”는 한 팀의 여러 웹 릴리스가 공유하는 자산이다. 기존 조직 VPC/NAT와 같은 공유 기반을 뜻하지 않는다.

조건과 제외 범위

HasDetails는 상세 버킷 이름, HasSharedAssets는 자산 버킷 도메인, RoutingEnabled는 라우팅 이미지 URI의 존재를 검사한다. 해당 값이 채워졌다는 사실만으로 객체·그래프·OAC 권한이 검증되지는 않는다. HasWebAcl과 HasViewerDomain은 distribution 속성 연결 조건이다. HasOriginCertificate는 TLS listener 준비이며 UseOriginTls 전환 완료와 다르다.

소스 범위에 다음 배포를 추가하지 않는다.

  • AgentCore Browser, Code Interpreter, Bedrock Knowledge Bases, online evaluations: 이 YAML과 실행 연결에 생성 근거 없음. 브라우저 회귀 테스트는 AgentCore Browser가 아니며, Memory 검색도 Knowledge Base 배포가 아니다.
  • GuardDuty 배포: ECS 실행 역할의 AWS 관리 sidecar 저장소 읽기 grant와 과거 계정 관측만 있다. AWS::GuardDuty::* 선언은 없다. 계정에서 자동 삽입된다면 리허설 때 실제 동작·추가 용량을 확인하며 임의로 켜거나 끄지 않는다.
  • Inspector 활성화 완료: ECR ScanOnPush만으로 계정 enhanced scanning/지속 검사 활성화를 입증하지 않는다. 과거 “발견 0건”은 새 이미지 결과가 아니다.
  • API Gateway, Route 53 hosted zone/record, NAT/VPC endpoint, RDS, OpenSearch, Kinesis/Firehose, 별도 KMS key, AWS Budgets: 이 템플릿들의 생성 리소스가 아니다. 지원 기능이나 ARN 이름으로 추측하지 않는다.
  • AgentCore API-key/OAuth credential provider: Gateway target의 GATEWAY_IAM_ROLE과 구분한다. 현재 Atlas의 외부 API 키는 수집 작업의 SSM 경계에 있다.

scripts/check.mjs는 Node/Python 회귀·cfn-lint·npm audit·앱 빌드를 실행한다. npm audit는 패키지 registry 통신이 필요하고 결과/빌드 파일을 작성하므로 “완전 오프라인·읽기 전용”이라고 부르지 않는다. scripts/verify.py와 live 브라우저·개인정보·복구 도구는 별도의 클라우드/네트워크 검사다. 교재 작성 중의 소스 검토만으로 이 검사들이 통과했다고 표시하지 않는다.
