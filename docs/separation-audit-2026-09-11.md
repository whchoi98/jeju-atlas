# 분리 구성과 기존 프로젝트 영향 점검

2026-09-11에 Git, 실제 ECS 작업 정의, AgentCore 설정, IAM 정책·시뮬레이션, S3, CloudTrail과 공개 health 응답을 읽기 전용으로 점검했다.

현재 실행 리소스는 분리되어 있다. 다만 기존 역할의 교차 로그 조회 권한과 분리 전에 변경한 기존 로그 보관 정책이 남아 있다.

| 항목 | 결과 |
|---|---|
| 저장소 | 제주 저장소와 `agentcore-cli`는 별도 Git 저장소 |
| AgentCore | Guide·Tools Runtime, Gateway, Memory, 실행 역할이 각각 별도 |
| 실행 연결 | 제주 ECS는 전용 JejuAtlas Guide, 기존 운영·스테이징 ECS는 Ohmyjeju Guide 사용 |
| 데이터 | 카탈로그·코드 배포물은 별도 S3 객체와 버킷 사용 |
| IAM | 상대 Runtime 호출·카탈로그 읽기/쓰기/삭제 26개 조합은 시뮬레이션상 `implicitDeny` |
| 운영 | 양쪽 Runtime READY, 공개 웹 health HTTP 200 |
| 공유 기반 | AWS 계정·VPC·Private Subnet·NAT·인증서·중앙 추적 경로 |

## 남아 있는 사항

1. 기존 Guide·Tools 역할의 로그 정책 범위가 넓다. 제주 Guide 로그 그룹에 대한 `logs:FilterLogEvents`가 IAM 시뮬레이션상 허용되었다. 실제 다른 프로젝트 로그를 조회하거나 로그 쓰기를 검증한 것은 아니다.
2. 기존 Guide·Tools 로그의 무기한 보관 정책을 14일로 변경한 과거 설정이 남아 있다. 변경 전후 기록과 현재 정책으로 확인했으며 실제 로그 손실을 확인한 것은 아니다.
3. 분리 전에는 기존 `main`에 Astra/Sol 관련 변경을 병합하고 공유 Runtime을 업데이트한 이력이 있다. 이후 기존 프로젝트가 해당 커밋을 되돌렸고 현재 소스·배포 기록은 Sonnet 5 유지 결정을 따른다.

후속 보완 대상은 기존 역할의 로그 범위를 해당 Ohmyjeju 로그 그룹으로 제한하는 것과 기존 로그 보관 정책을 정하는 것이다. 이 점검에서는 기존 프로젝트의 파일, IAM 정책, AWS 리소스를 수정하지 않았다.

IAM 시뮬레이션 결과는 지정한 역할·작업·리소스·조건에 한정된다. CloudTrail 관리 이벤트 조회만으로 모든 호출·데이터 접근의 부재를 증명할 수는 없다. 실행 연결의 분리와 계정·네트워크 차원의 완전한 격리는 구분해야 한다.

같은 날 작업 디렉터리를 `jeju-atlas`로 통합하면서 전체 감사 보고서와 JSON 증거는 `.local/separation-audit-20260911/`로 복사했다. 해당 운영 증거는 Git 업로드 대상에서 제외한다. 디렉터리 변경으로 위 두 설정이 수정되지는 않았다.
