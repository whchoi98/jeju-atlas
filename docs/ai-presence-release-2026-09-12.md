# AI 이용 한도 해제와 접속 집계

사용자 요청에 따라 앱의 일일·시간당·전체 및 사용자별 동시 AI 이용 한도를 해제해 운영 배포했다.
같은 대화의 동시 갱신과 같은 요청 ID의 중복 실행은 별도로 방지한다.
화면에는 현재 접속과 누적 접속 수를 표시한다.

## 동작

- 운영 설정은 `GuideLimitsEnabled: "false"`이다.
- `/api/config`의 `guide.limits_enabled`는 false, 세 가지 cap 값은 null이다.
- 독립적인 대화는 같은 브라우저에서도 동시에 처리할 수 있다.
- 이미 시작한 요청의 결과가 불명확하면 같은 요청을 자동 재실행하지 않는다.
- 같은 대화가 진행 중이면 `conversation_busy`로 구분한다.
- 요청 검증·세션·CSRF·응답 제한 시간과 AWS 자체 할당량은 별도다.

접속 표시는 `접속 N · 누적 M`이며 브라우저 세션 기준이다.
현재 수는 최근 90초에 접속이 확인된 세션, 누적 수는 이 기능 도입 후 각 세션의 첫 접속이다.
새로고침과 같은 세션의 여러 탭은 중복 집계하지 않는다.
집계 시작 전의 접속 수나 실제 사람 수를 추정하지 않는다.

전용 `jeju-3d-presence` 테이블을 모든 ECS 태스크가 공유한다.
활성 기록은 시간 조건으로 계산하며, TTL 삭제 지연으로 접속 수를 늘리지 않는다.
최초 등록과 누적 증가를 원자적으로 처리하고 누적 등록 기록은 재배포 후에도 유지한다.
외부 API에는 수·기준 시각만 반환하며 세션 식별자·IP·검색어·좌표·대화는 포함하지 않는다.

연결이 끊기거나 집계가 실패하면 마지막 확인 값 또는 확인 불가를 표시한다.
창 간 초기 세션 조정을 지원하지 않는 환경에서는 접속 등록을 하지 않고 확인 불가로 안내한다.
그 환경의 지도 등 다른 앱 기능은 유지한다.

제한 해제 검사는 시간 내 40회 요청과 여러 서비스 인스턴스의 16개 동시 세션,
같은 사용자의 독립 대화, 요청 재전송·결과 불명·이전 소유자 보호를 포함한다.
브라우저 검사에서는 세션 3개가 질문 4개를 동시에 처리했다.
해당 검사는 실제 모델 대신 통제된 응답을 사용했다.

별도 검토에서 접속 갱신과 조회의 경합 및 쿠키 없는 첫 창들의 경합을 재현해 수정했다.
전자는 활성 방문자가 0으로 빠지지 않도록 조회 조건을 고쳤고,
후자는 실제 설정 요청을 창 간에 직렬화했다.

실제 브라우저 세션 세 개에서 동시에 질문해 세 응답 모두 오류 없이 `done`까지 도달했다.

자료를 찾지 못했다. 이 두 검색 품질 문제는 전체 기능 확장의 후속 조사 대상으로 남겼다.
