# 제주 이동 경로와 3D 탐색

사용자 목표: “추가 기능들을 적용해 주세요. 도보 예상 거리, 차량 이동시 예상 거리, 주요 관광지 3D 제공 등 기존 카카오맵이나 네이버맵을 능가하는 기능이나 해당 맵에서 제공해주는 서비스들에 대해서 추가.”

## 사용자 동작과 완료 조건

1. **도보·차량 비교**: 내 여행에 두 장소 이상을 담으면 도보와 차량의 실제 도로·보행로 경로, 예상 거리와 시간이 각각 계산된다. 이동 수단을 선택하면 해당 경로가 지도에 표시된다. 연결선의 길이를 도로 거리로 표시하지 않는다.
2. **여행 계획**: 최대 12곳의 방문 순서와 체류 시간을 유지하면서 구간별 거리·시간, 전체 이동 시간, 체류 시간을 포함한 계획 시간을 제공한다. 이동 순서를 바꾸면 이전 경로를 즉시 제거하고 다시 계산한다.
3. **출발·도착 설정**: 장소 상세에서 출발지/도착지로 지정하고, 사용자 조작으로 지도 중심 또는 현재 위치를 출발지로 사용할 수 있다. 위치 권한 거절·제주 밖 위치·길에 연결되지 않는 좌표를 안내한다.
4. **길 안내와 내보내기**: 선택한 이동 수단의 구간별 방향 안내와 도로명을 제공하고, 계산한 경로를 GPX로 내려받을 수 있다. 공유 코스는 이동 수단도 복원한다.
5. **관광지 3D 탐색**: 기존 주요 지형 명소 12곳을 별도 3D 탐색 화면에서 고르고, 지형에 접근·회전·전체 보기·실제 고도 비율 복원이 가능하다. 선택 명소의 기존 공식 사진·상세 보기와 연결한다. 수동 조작·탭 비활성화·동작 감소 설정에서 자동 회전을 중지한다.
6. **경로와 지형 연결**: 계산한 실제 경로를 3D로 미리 살펴보고, 같은 경로의 고도 단면·오르막·내리막을 확인한다. 높이 미확인 구간을 0m로 간주하지 않는다.
7. **거리 재기**: 지도에서 여러 점을 지정해 구간·전체 직선 거리를 재고, 마지막 점 취소와 초기화를 제공한다. 경로 계산과 측정 결과를 구별한다.
8. **운영 반영**: 기존 CloudFront→HTTPS ALB→Private ECS Fargate 구성을 재사용해 배포한다. 새 도보·차량 경로와 주요 3D 동작을 실제 공개 서비스에서 검증한다. 기존 카탈로그·AI·올레길·한영 전환·나눔스퀘어·모바일 UI 회귀를 확인한다.
9. **참조 프로젝트와 독립**: 추가 사용자 지시 “`/home/ec2-user/my-project/agentcore-cli`와 영향 없이 독립성 유지”를 따른다. 참조 소스는 검증된 커밋에서 한 번 복사해 이 프로젝트가 소유하고, 배포·실행 때 참조 디렉토리를 사용하지 않는다. 제주 전용 Runtime·Tools Runtime·Gateway·Memory·IAM·로그·코드 아티팩트·카탈로그를 사용하도록 전환한다. 기존 `AgentCore-Ohmyjeju-default` 스택·메모리·역할·코드를 변경하거나 삭제하지 않는다. 기존 VPC·NAT 재사용 지시는 유지한다.

일반 지도와의 비교는 위의 실제 동작으로 판단한다. 실시간 교통·대중교통 배차·로드뷰·사진측량 모델이 없는 상태에서 해당 기능을 제공한다고 표시하지 않는다.

## 데이터와 경로 엔진

Amazon Location 공식 coverage 표는 한국 경로를 지원하지 않는다. 기존 참조 Agent의 경로 도구 또한 실제 도보 경로 재사용 가능 여부를 코드로 확인한다.

기본 엔진은 공식 ARM64 Valhalla 3.8.3이며, 공식 이미지 digest를 고정한다. Geofabrik의 한국 OSM PBF에서 제주 서비스 영역과 주변 여유 영역을 추출하고, 보행로·차량 통행·일방통행·회전 제한이 포함된 경로 그래프를 빌드한다. 다운로드 시점·원본 수정 시각·체크섬·추출 범위·엔진 버전을 manifest에 기록한다.

공개 데모 경로 서버를 운영 의존성으로 사용하지 않는다. 경로 그래프는 전용 컨테이너 이미지에 포함해 기존 ECS 작업의 로컬 사이드카로 실행한다. 앱 서버만 loopback HTTP로 접근하며 새로운 외부 수신 포트를 열지 않는다. 데이터 빌드는 배포 이전에 수행하고 작업 시작 때 재다운로드하지 않는다.

예상 시간은 OSM와 엔진의 속도·보행 가정에 따른 값이다. 실시간 정체를 반영하지 않는다는 표시, OSM 출처·기준 시각, 경로 종료점과 요청 위치 사이의 차이를 노출한다. 엔진의 ferry 회피는 완전 배제가 아니므로 ferry가 들어간 결과는 도보/차량만의 경로로 제공하지 않는다. 연결되지 않는 구간에 임의 직선을 덧붙이지 않는다.

고도는 출처가 확인된 실제 DEM으로 계산한다. 지형 배율과 무관한 실제 높이를 사용한다. 3D 명소도 같은 DEM과 위성 영상의 지형 표현이며, 개별 건물·절벽을 정밀 촬영한 모델로 설명하지 않는다.

## 경로 API 계약

`POST /api/routes` 요청:

```ts
type RouteMode = 'walk' | 'car';
type RouteRequest = {
  mode: RouteMode;
  locale: 'ko' | 'en';
  stops: { lng: number; lat: number }[]; // 2–12개
};
```

모든 위치는 기존 서비스 범위 `126.15 <= lng <= 126.98`, `33.1 <= lat <= 33.6` 안에 있어야 한다. 도착·출발 이름은 엔진에 보내지 않는다. 좌표·고객 질문·응답 본문은 로그에 남기지 않는다.

`shared/routing-types.ts`가 프런트엔드 계약을 소유한다. 성공 결과는 다음 의미를 유지한다.

```ts
type RouteSource = {
  provider: 'valhalla';
  data: 'OpenStreetMap';
  attribution: string;
  url: string;
  data_updated_at: string | null;
};
type RouteStep = {
  instruction: string;
  distance_m: number;
  duration_s: number;
  start_index: number;
  end_index: number;
};
type RouteLeg = {
  distance_m: number;
  duration_s: number;
  coordinates: [number, number][];
  steps: RouteStep[];
};
type RouteSuccess = {
  available: true;
  mode: RouteMode;
  source: RouteSource;
  distance_m: number;
  duration_s: number;
  legs: RouteLeg[];
  coordinates: [number, number][];
  snapped: { lng: number; lat: number; distance_m: number }[];
  warnings: string[];
  traffic: 'not_live';
};
type RouteUnavailable = {
  available: false;
  mode: RouteMode;
  source: RouteSource;
  code: 'no_route' | 'endpoint_unreachable' | 'ferry_required' | 'routing_unavailable';
};
type RouteResult = RouteSuccess | RouteUnavailable;
```

입력 검증 실패는 400, 세션/CSRF 실패는 401/403, 부하 상한은 429, 서비스 중단은 503으로 처리한다. 연결할 수 없는 경로는 `RouteUnavailable`을 반환한다. 이용자에게는 한국어 또는 영어 안내를 표시한다.

`GET /api/config`에 `features.routing`, `routing.enabled`, `routing.csrf_token`, `routing.modes`, `routing.source`를 추가한다. 기존 서명 쿠키와 CSRF를 사용하되 AI의 모델 호출이나 쿼터를 소모하지 않는다. 두 CloudFront 호스트에서도 기존 세션 증명 방식이 동작해야 한다.

엔진 주소는 배포 구성에서 정해진 loopback 주소만 사용한다. 사용자가 URL·엔진 파라미터·행동 이름을 주입할 수 없다. 요청 크기·경유지 수·응답 크기·좌표 개수·시간 제한·동시 요청·캐시 크기를 제한한다. 장애는 지도 전체를 멈추지 않는다.

## 화면 구성

기존 나눔스퀘어와 지도 색 체계를 유지한다. 내 여행 요약 아래에 도보/차량 비교 선택, 계획 시간, 구간 안내와 경로 내보내기를 놓는다. 지도에는 선택한 이동 수단의 경로와 출발·도착·경유지 번호를 표시한다.

탐색의 지형 명소 영역은 3D 명소 탐색으로 확장하고 현재 지도 위에 간결한 회전·시점 도구를 제공한다. 측정 모드와 자동 미리보기는 서로 정지시키며, 지도 수동 조작을 우선한다. 폰트·언어 변경에 따라 동적 버튼·시간·오류·지도 설명도 갱신한다.

고도 단면은 경로 아래에 표시하고 해당 거리의 지도 위치와 연결한다. 확인 가능한 표본 비율을 표시하며 부분 높이 데이터로 전체 상승량을 단정하지 않는다.

## 검증과 근거

- 경로 API: 실제 네트워크 접근과 fixture 기반 계약 검증을 나눈다. 좌표 경계, 잘못된 모드, 12개 제한, 일방통행/도보 차이, 연결 실패, ferry, 응답 크기, 중단, 제한, CSRF, 본문 비기록을 확인한다.
- 데이터: PBF 원본·추출·그래프 hash, 엔진 버전, OSM 시각을 저장한다. 실제 제주 경로 세 쌍 이상에서 차량/도보 형상과 거리를 검증한다.
- UI: 장소 지정→두 수단 계산→전환→순서 변경→GPX/공유→새로고침 복원, 권한 거절, 한국어/영어, 모바일을 브라우저에서 검증한다.
- 3D: 주요 명소 선택, DEM 로드, 실제 회전/중지, 수동 조작, 동작 감소 설정, 경로 미리보기, 고도 부족, 측정 취소/초기화를 브라우저에서 확인한다.
- 운영: immutable 앱/경로 이미지, 자원 사용 측정, CloudFormation 변경 범위, 컨테이너 health, CloudFront 공개 경로 응답과 기존 기능의 회귀 근거를 `.local/`에 남긴다.
- 독립성: ECS의 실제 Runtime ARN·S3 카탈로그와 새 Runtime의 Gateway/Memory/IAM/코드 아티팩트를 추적해 모두 제주 소유인지 확인한다. 원본 디렉토리가 없어도 패키징·검증할 수 있어야 한다. 기존 공유 스택에 대한 쓰기 동작이 없는지 배포 계획과 실행 대상을 점검한다.
