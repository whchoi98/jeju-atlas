# 공식 장소 상세와 올레길 둘러보기

2026-09-10 수집 자료와 구현 기준입니다. 배포 버전과 실제 서비스 검증은
[최종 배포 확인](details-olle-release-2026-09-10.md)에 남깁니다.

## 장소 상세

원본 6,724곳의 ID·이름·좌표를 유지하면서 공식 제공처 자료를
`official_details`에 별도로 연결합니다. 137개 시드 중 94곳과 OSM 장소
250곳, 총 **344곳**에 제공처 기록 **700건**이 연결됐습니다.

| 제공처·언어 | 기록 |
|---|---:|
| 한국관광공사 TourAPI 국문 | 210 |
| 비짓제주 국문 | 245 |
| 비짓제주 영문 | 245 |

사진은 제공처 기록 기준 **707장**, 중복 URL을 제외한 미디어는 **689개**입니다.
이 수치는 기존 원본 카탈로그 사진 수에 더한 전체 서비스 집계가 아닙니다.
새 사진의 선언된 이용조건은 KOGL-1 184장, KOGL-3 523장입니다.
허용한 원본만 바이트 그대로 미러링하며, 자르기·재인코딩을 하지 않습니다.
비짓제주 키가 유효하다는 이유로 비짓제주 사진을 자동 게시하지 않습니다.

상세 화면에서 갤러리, 소개, 주소·전화·홈페이지, 이용시간·휴무일·요금·주차
등 제공된 항목을 볼 수 있습니다. 제공처별 탭과 조회 시각을 표시합니다.
영문 선택 시 비짓제주 영문을 사용하고, 영문이 없는 TourAPI 이용 정보는
한국어 원문임을 표시해 유지합니다. 장소별 공개 원문 주소가 없는 TourAPI
포털 링크는 ‘정보 제공처’로 표시합니다.

정확한 이름·카테고리·거리와 후보의 유일성을 검사합니다. 시드의 미검증 좌표는
2km, OSM 좌표는 150m 한도를 사용하며 모호한 매칭은 거절합니다.
매칭 정보가 있다는 사실만으로 `reviewed` 상태를 만들거나 기본 좌표를 바꾸지
않습니다. 사진 없는 장소·제공처가 하나뿐인 장소도 기존 상세와 함께 표시됩니다.

## 저장과 갱신

키는 다음 두 SSM SecureString에서 수집 작업만 읽습니다.

```text
/jeju-atlas/visitjeju-api-key
/jeju-atlas/tourapi-service-key
```

`Jeju3dData`의 전용 비공개 버킷에 `place-details/latest.json`과 이력을
저장합니다. 허용한 이미지의 `media/`만 CloudFront OAC로 제공합니다.
웹 태스크와 AgentCore Tools는 상세 스냅샷 한 개를 읽을 수 있고,
제공처 키를 읽거나 원본 카탈로그를 쓸 수 없습니다.

갱신 일정은 한국 시각 03:00입니다. 한 번에 최대 900곳을 시도하며
15분 실행 한도와 종료 여유 30초, API 작업별 호출 상한을 둡니다.
실제로 시도한 `last_attempt`으로 다음 대상을 순환합니다. 보존한
제공처 자료의 `fetched_at`을 새 조회 시각으로 꾸미지 않습니다.
한 실행에서 전체를 처리하지 못하면 다음 일정에서 이어서 순환하므로,
매일 모든 장소를 다시 확인했다는 뜻은 아닙니다.

범주별 전체 페이지가 정상 수집되어야 매칭 후보에 반영합니다.
제공처의 페이지 누락·모호한 ID·통신 실패 시 마지막 정상 자료를 유지합니다.
동시 작업은 ETag 조건부 쓰기로 서로의 결과를 덮어쓰지 않습니다.
14일 넘은 기록은 API와 AI에서 오래된 자료로 표시합니다.

실제 Fargate 검증에서 TourAPI 전체 목록과 비짓제주 관광·쇼핑 목록을 수집했습니다.
비짓제주 음식점(`c4`)은 한국어·영어 모두 제공처 총건수와 고유 ID 수가 달라
한 번 재수집한 뒤에도 해당 범주의 새 매칭을 보류했습니다. 기존 음식점 자료를
지우거나 불완전한 목록을 완전한 목록으로 취급하지 않습니다.
두 대표 장소의 갱신·발행과 수집기·GuardDuty 컨테이너의 정상 종료를 확인하고
03:00 일정을 활성화했습니다.

최초 설치에서는 운영 권한이 있는 배포 호스트에서 첫 스냅샷을 발행한 뒤
수집 태스크를 실행합니다. 빈 버킷에서 `GetObject`만 허용된 태스크 역할은
없는 객체에 403을 받을 수 있으므로, 최초 스냅샷 준비를 생략하지 않습니다.

```bash
python3 scripts/deploy.py build-data-push
python3 scripts/deploy.py plan-data
# .local/data-change-set.json 검토
python3 scripts/deploy.py apply-data
python3 scripts/deploy.py status-data
```

`infra/data-settings.json`의 `ScheduleState`로 일정을 관리합니다.
실제 태스크의 종료 코드와 수집 결과를 확인한 뒤 활성화합니다.
데이터 수집 로그에는 질문·API 키·요청 URL을 남기지 않습니다.

계정의 GuardDuty 자동 관리가 삽입하는 Fargate 보안 에이전트를 위해,
실행 역할은 앱 저장소 외에 AWS의 서울 리전
`914738172881:repository/aws-guardduty-agent-fargate`만 추가로 읽습니다.
계정의 GuardDuty 설정을 변경하거나 보안 에이전트를 끄지 않습니다.

## 올레길 둘러보기

지도 위 ‘둘러보기 테마’에서 기존 **제주 한 바퀴**와 올레길을 선택합니다.
선택할 때만 경로를 내려받고, 실제 선을 따라 3D 카메라가 이동합니다.
멈춤 버튼·Escape·수동 지도 조작으로 종료할 수 있습니다.
한영 전환과 모바일 화면을 지원합니다.

**18개 경로 항목을 재생**할 수 있습니다.

- 1, 2, 3-A, 3-B, 4, 5, 6, 7, 8, 9, 10, 11, 16, 18, 19, 20코스
- 14코스 일부 구간 약 4.64km, 21코스 일부 구간 약 1.30km

14·21코스는 코스명에도 ‘일부 구간’을 표시합니다. 모든 경로는 OSM의
참고 자료이며 현재 공식 코스 전체와 일치한다고 검증한 자료는 아닙니다.
자료가 없는 11개 항목은 재생할 수 없음을 표시합니다.

경로 출처는 OpenStreetMap 관계 객체이며 ODbL-1.0 조건을 표시합니다.
원래 선의 점만 8m 허용 오차로 단순화하고, 분리된 구간을 임의로 연결하지
않습니다. 표시 거리는 실제 확보한 선의 길이입니다. OSM 수정 시각과
자료 조회 시각은 서로 구분합니다.

공식 두루누비의 과거 GPX도 조사했으나 해당 자료의 재배포 조건과 현재
코스 대응이 확정되지 않아 이 배포 자료에는 포함하지 않았습니다.

## 검증 자료

- `.local/official-details-expanded-validation.json`: 344곳·700개 기록 검증
- `.local/parent-rich-detail-final/report.json`: 실제 자료의 제공처·언어·사진 유무와 키보드 검사
- `.local/parent-olle-browser/report.json`: 3D 재생·중단·한영·모바일 검사
- `.local/data-worker-smoke.json`: 최초 Private Fargate 수집 실행
- `.local/data-worker-final-smoke.json`: 최종 수집기·GuardDuty 종료 코드와 부분 제공처 실패 보존
- `.local/data-image-final-scan.json`: 최종 데이터 이미지 검사
- `.local/olle-final/report.json`: 최종 공개 서비스 올레길 검사
- `.local/official-details-final/report.json`: 실제 사진·한영 상세·시간 범위·AI 도구와 답변 확인

브라우저 단위 검사에서는 이미지 응답을 제어합니다. 실제 CDN 이미지와
AgentCore 응답은 별도의 운영 서비스 검사로 확인합니다.
